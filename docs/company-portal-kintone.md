# 企業別URLのkintoneデータ

App10（オールマイト）とApp49（てずくーる）をサーバー側で読み取り、既存の企業別URLとCSVへ反映する。申請システムを経由しない案件と、その法人名もURL発行対象に含める。kintoneへ書き戻さず、申請・在庫予定も新規作成しない。

法人名は両アプリとも文字列__1行__1。企業名の既存の正規化ルールを使う。申請とkintoneは「アプリID＋管理番号」で統合し、kintoneの法人名・利用日・場所・内容・金額を優先する。法人名で絞る前に統合するので、kintoneで法人を変更した案件を旧企業に残さない。内訳の社内レンタル費用を補完する場合は同一法人だけ。住所や商品などは申請側の古い内容で補完しない。

App10の機器④はレンタル機材_3、⑤はレンタル機材_2。App49はレンタル機材の登録名をそのまま表示し、コンテンツ／数値の①〜⑩を商品・数量として表示する。配送のみから利用日を推定せず、kintone利用日が空なら表示対象外の件数に含める。

金額は税抜。App10は利用金額①〜⑤と計算（実フォームで「機器代＋配送費−調整額」を確認）。App49は基本料（数値_9）＋売上額①〜⑩（数値_10,11,21,20,19,18,17,16,15,14）＋配送費−調整額。営業代行費用と最終売上額は社内採算用なので取得も表示もしない。金額のない案件を0円に変えない。合計は調整後の値を使い、CSVも同じ値にする。

読み取りは500件ずつ$idで続きから取得。各アプリ最大20000件、超過時は不完全な一覧を返さずエラー。サーバーだけに最小限の項目を60秒キャッシュし、ページへ最終取得時刻を表示する。API障害時に空の正常な一覧へすり替えない。初回失敗はエラー、既存キャッシュは更新時刻から鮮度を判断できる。

kintoneには登録・確定を区別できる共通ステータスがないため「登録済み」として表示する。見積書／請求書のチェックは書類出力用で、契約確定の判定には使わない。メール・電話・担当者連絡先・備考・営業代行費用は表示データに含まれない。

検証：両アプリの現在のフィールドと料金計算を読み取り確認。全1160件を取得して変換・統合・当月抽出・CSV出力を確認。架空データで法人変更時の旧企業への漏れ、事業をまたぐ同じ管理番号、金額未登録／0円、商品④⑤、教材数量と社内情報の除外を検証した。
