# 手動番号・在庫予定の編集（2026-10-24）

## 動作
- 自動で空き番号に詰め直さない。申請・仮押さえは番号指定まで「未割当」に表示する。元シートの手入力行番号は初期番号として引き継ぐ。
- 予定クリックで商品・番号・担当者・店舗・利用日・配送日・集荷日・確保期間を編集する。番号は手動選択、PCでは予定を別番号の行へドラッグできる。横方向に動かしても日程は変わらない。
- 確保期間は出荷・移動・返却・点検まで含めて担当者が指定する。配送サイクルを推測して自動割当しない。端点の日付を含め、他案件の同じ商品・番号と重なる保存を拒否する。予備番号、期間中に台数変更で対象外になる番号も拒否する。
- 延長と親申請は同じ機器グループとして番号を共有する。既存シートの競合は赤い競合行で表示し、勝手な再配置や非表示にしない。
- 編集は在庫運用上の変更として別保存。元申請、kintone、元シートの手入力領域は変更しない。申請の取消・kintone変更は既存の申請業務から行う。
- 削除は在庫表での取り消し。削除済み一覧から復元できる。元の申請・記録と監査履歴を保持する。
- 仮押さえは同商品複数台・異なる商品の一括登録に対応。各台で番号指定または未割当を選択する。1回20商品行・合計100台まで。全台を1トランザクションで保存し、同一送信の再試行では増殖しない。
- 公開申請は同じ商品を複数枠で選択できる。既存申請枠の上限5台を維持する。各枠を独立した1台としてFMT・在庫管理へ渡す。
- コンテンツ切替タブは画面上部へ固定する。

## 保全・排他制御
`20261024050000_inventory_manual_operations.sql` を本番適用済み。別表の予定変更、番号、バッチ履歴、変更世代を追加。新しい保存RPCはサービス側専用で、認証済みの有効管理者を検証する。在庫の完全なスナップショットから候補期間を生成し、DBのロック下で世代・競合を検証する。古い画面からの上書きを拒否する。通常管理者へ新表の直接更新権限を与えていない。
