# 管理者の招待・パスワード設定

2026-11-24、Supabase に rental の `redirectTo` を指定しても、生成結果の `redirect_to` が `https://invoice-tool-r30s.onrender.com` になることを使い捨ての Auth アカウントで確認した。共通の Auth URL 設定によって別アプリへ戻されていた。全体設定を変更すると請求書側にも影響するため、レンタル側のリンクを独立させた。

- 新規招待・招待再送・再設定は `generateLink` でワンタイムトークンを生成し、既存 SMTP で日本語のレンタル専用メールを送信する。常時 CC は付けない。
- URL の origin は管理画面のリクエストと同じものを使う。共有環境変数の Site URL、Supabase の action_link / redirect_to は利用しない。
- トークンは `/auth/set-password#token_hash=…&type=invite|recovery` の fragment に置き、アクセスログ・Referer に送らない。画面で `verifyOtp` し URL から削除する。
- 既存 Auth アカウントは recovery で再利用し、再送・再設定では管理者行の Auth ID と照合する。
- 無効・期限切れ・使用済みリンク、単に既存のログインだけある場合は設定を許可しない。
- 新規招待は管理者行と担当事業の保存後にメールを送る。送信失敗時はエラーを返し、管理者一覧の再送から回復する。SMTP 未設定時も成功扱いにしない。
- パスワード保存後に自分の管理者行を有効化し、成功した場合だけ管理画面へ進む。停止ユーザーの有効化は禁止。
- 旧メールは遷移先を後から修復できないため、管理者一覧から再送が必要。

確認: 専用 URL / invite・recovery / トークン欠落・不正種別の自動テスト。実サービス上の使い捨て Auth アカウントで招待と回復の検証、使用済み拒否、同一 ID の再利用を確認し削除。実メール送信・パスワード変更・管理者権限付与は行わない。
