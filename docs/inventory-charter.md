# 在庫予定のチャーター便

予定の編集画面の配送・集荷それぞれで通常配送、チャーター便、手配なしを選ぶ。チャーター便は時刻（HH:MM）が必須。通常配送へ戻すと時刻をクリアする。

予定の編集画面では利用開始・終了、納品・集荷、確保開始・終了の6日付を独立して設定できる。日付や通常配送／チャーターの選択を変えても、ほかの入力済み日付は変更しない。手配なしにするとその方向の日付を解除し、再度有効にした時に空欄ならチャーターは利用日、通常配送は前日・翌日を初期値にする。確保期間は利用・納品・集荷日をすべて含める必要がある。倉庫休業日に発送できないルールと休業明けの受け取りによる在庫確保は引き続き適用する。時刻単位の在庫入れ替えは行わず、在庫は日単位で判定する。

手配情報は既存の `transport` メタデータに保存する。仮押さえから本登録への移行、新規kintone登録、登録済み案件の変更、延長コピーに引き継ぐ。フィールドはApp10/49/11で実フォームを確認済み：配送=手配種別、納品_時間、集荷=集荷_手配種別、集荷_時刻。App11へも種別・日付・時刻を連携する。

既存の申請詳細の手配変更画面との競合は更新時刻で判定する。在庫側の指定をサーバー保存時刻と一緒に保持し、申請詳細側で明示変更した場合はDBトリガーでその更新時刻を記録する。後から変更された設定を採用する。元の請求内容や不変のコピー申請JSONを書き換えるための例外は追加しない。

検証：同日配送/集荷、片道チャーター、通常配送へ戻した時の時刻クリア、不正時刻、仮押さえ保存データ、登録・配送管理のフィールド、延長元の日付/時刻クリア、別画面での変更優先を確認。画面からの保存はローカルの架空予定で検証し、実際の顧客予定を作成・変更していない。
