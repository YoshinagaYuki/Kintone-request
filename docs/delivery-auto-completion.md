# 配達完了の自動確認（2026-11-27）

## 対応

西濃運輸の公式公開追跡ページを参照し、同じ10桁送り状番号の結果行で「配達済みです」と明示された場合だけ完了にする。現在配達中・配達店到着などは未完了のまま状況を表示。対象は納品日が当日までの過去30日間。

佐川の問い合わせAPIは公式案内で停止中。今回は佐川・ヤマト・複数伝票・番号不明は手動確認を残す。西濃とセイノースーパーエクスプレスは別扱い。

## 実行

- Supabase Cronで30分ごとに両事業を確認。専用のサーバー間トークンで、自システムのPOST `/api/cron/delivery-status`を呼ぶ。トークンはサーバー専用・RLS有効の設定テーブルに保存し、ブラウザやソースに公開しない。
- 納品予定を開いた際と、表示中15分ごとにも確認。1事業1回8件、同時照会2件、各照会10秒まで。確認時刻の古い順に処理。
- DBの取得枠と15分キャッシュで重複照会を防止。通信失敗・ページ変更・番号不一致・古い受付日・結果不明は自動完了しない。固定公式ホストのみ取得。
- 配達済み取得後、最新の管理表とkintone伝票を再取得して同じ案件・日付・配送業者・番号であることを再確認。伝票が変わった自動完了は再確認対象に戻す。
- 人がチェックを変更した場合は手動判断を優先し、処理中の自動応答も上書きできない。「自動確認に戻す」で再開できる。
- 自動判定の完了には「西濃運輸の配達済み情報で自動確認」を表示。時刻は確認・記録時刻であり、実配達時刻とは区別。
- 在庫、日付、申請、kintone、メールには変更を加えない。完了記録と自動確認の管理情報のみ更新。

## 確認

関連テスト356件、typecheck、production build成功。実際の西濃結果で配達済み・配達中・配達店到着を確認。
DBで二重実行防止、実際の完了更新、伝票変更時の再確認、手動変更との競合、匿名・一般認証ロールからのアクセス拒否を確認。QA用データは全件ロールバック。
新規テーブルはサーバー専用のRLS/no-policy。既存の請求システム等の権限・設定は変更していない。
