# 日程の転記と照合

## 日付の正

新規作成・延長ともレンタル管理表の日付を正とする。kintoneの日付を申請・在庫表へ逆転記して補正しない。利用開始・利用最終・納品・集荷は別々の DATE 値として転記する。通常配送の前日／翌日計算は入力画面で行い、転記時は保存済み日付に加減算しない。倉庫の発送可能日・返却日・点検期間を顧客の納品／集荷日に置き換えない。チャーターの利用当日配送／集荷、管理者が指定した別日、年末年始を跨ぐ日付もそのまま保持する。

- 仮押さえから本登録・承認前編集では、標準日程だった納品／集荷は利用期間の変更に追従する。手動指定済みの日付は維持する。
- 今回の改修・既存データ修正はオールマイトのみ。てずくーるの入力画面・登録日程・既存データは変更しない。

## 連携完了の条件

`requestDateSnapshot` で申請の日付を正規化する。新規書込後に手配管理の4日付を取得して照合してから、採番・配送連携を続ける。配送管理でも納品／集荷日を取得して照合する。延長・コピーも作成日程と最終の配送日程を照合する。不一致は登録失敗として返し、完了メール・通知へ進めない。既存の登録IDは保持し、再実行で重複作成しない。相違した日付は推測で上書きせず、管理者の確認を求める。

配送管理への転記は日付・時刻の空欄も反映する。手配不要にしても旧日付だけ残る状態を作らない。同じ管理番号の配送レコードが複数ある場合も停止する。新規登録履歴・配送連携履歴には日付のスナップショットを残す。

## 読取専用の全件監査

```
npx tsx scripts/audit-kintone-dates.ts --out /absolute/path/audit.json
```

申請を全件読み、管理番号とレコードIDを確認して App10 と App11 を照合する。転記済み申請だけでなく、自動変更した延長元案件の旧集荷日残存も確認する。削除済み・延長による意図的な旧集荷取消は区別する。このスクリプトはデータ書込・メール・通知・再登録を行わない。

## 検証

通常の翌日集荷、利用最終日変更、手動日程保持、年越し、チャーター当日、空欄化、保存後の不一致検出を確認する。実顧客へのテストメール、新規の実案件登録は行わない。
