# オールマイト在庫管理・最終機能（2026-10-23）

## 実装

- ガントの標準表示は1ヶ月。1週間・2週間・3ヶ月・6ヶ月、開始・終了指定も維持。
- 商品マスタの総在庫・内予備に加えて、日付付きの在庫変更予定を登録可能。予定日以後の日別計算に適用。
- 延長は元申請から承認済みの子申請を作成。延長分の日付で料金を再計算し、新管理番号を発行。配送不要・配送/集荷連絡先空欄・選択した集荷日でApp10/11へ連携する。
- 新規レコードを手配不要の下書きで準備し、旧案件の集荷を不要に切り替えた後、新集荷を有効化。連携キー、番号保存、進捗チェックポイント、排他リース、revision照合で失敗から再開する。結果不明の新規登録は無条件再作成しない。
- 延長元と子申請の通常編集・削除・手配変更をDBでも防止。連鎖延長の同一商品を重複計上せず、旧集荷マークは完了後非表示。
- 既に配送会社へ依頼済みの集荷取消は、kintoneの不要区分だけでは依頼自体を取り消せない。追跡番号/手配済みのとき要確認を表示する。延長処理はメール/チャットを送信しない。
- Sheets向け読取専用CSVは在庫項目のみ。住所・電話・メール・金額を出さない。登録件数上限や不正日付で不完全なデータを正常同期として返さない。数式注入対策あり。

## 運用

- 標準画面: https://kintone-request.vercel.app/admin/inventory/allmight
- 延長は登録済み申請の詳細から実行。失敗時は子申請の詳細にある延長専用再実行を使う。処理中リースは5分。
- SheetsはIMPORTDATAによる読取連携。Google仕様上、開いている間の更新確認は約1時間おき。閉じた文書への即時同期は保証しない。
- 読取キーは本番環境変数INVENTORY_SHEETS_TOKENに保存。シートの読取数式にも含まれるため、対象はシート共有相当の在庫情報に限定。キーにアプリ/DBの更新権限はない。
- INVENTORY_EXTENSIONS_ENABLED=falseで延長外部処理を停止可能。停止時も通常新規配送へフォールバックしない。
- 新規マイグレーション2本はSQL Editor経由で適用。CLI migration履歴とは照合が必要。再適用禁止。

## 検証範囲

型チェック、本番ビルド、在庫テスト22件、ローカルPostgreSQL互換環境でRLS・監査・延長の承認/排他/再実行/原子的完了を検証。kintone連携はモックで失敗復旧、元日付変更、重複防止を検証。本番の実案件を延長して請求・集荷を変更する試験は行わない。

## 本番確認結果

- 8商品の基準数と2件の変更予定を登録。あひるサンダーv2の日別残数が11月1日から5台減ることを本番表示で確認。
- 8商品タブのA250に見出し、A251に6ヶ月の読取連携を設置。各シートに空き1000行を追加。全商品で読込エラーなし。
- 元シートの入力済みセルと元の結合範囲を再取得したExcelデータで照合し、既存値の変更・結合解除が残っていないことを確認。検証中に旧欄で新たな営業入力3セルを検出したが、自動処理の対象外として保持。
- 8商品向けの本番CSVで6ヶ月分の見出しを確認。キーなし・不正キーは401。
- 延長フォームの項目と申請詳細リンクを本番で確認。通常承認と同様、対象申請の担当事業権限をAPI・再実行処理で照合。担当外/停止管理者/別事業の拒否をテスト。

## 表形式の変更（2026-10-23・画像フィードバック）

- 商品ごとのタブ、1台あたり担当者/イベント場所の2段表示、期間を結合した店舗名、空き枠、下段のグレーの予備枠に変更。標準1ヶ月を維持。
- 案件表示の行番号は自動配置の表示枠で、実物の個体番号ではない。延長の親子は同じ表示枠を使う。予備へ自動的に割り当てず、超過は別の赤い行で表示。予定日以降の在庫減少も考慮。
- 空き枠から1台の仮押さえを追加。担当者のプルダウン風ボタンで案件詳細を確認し、申請内容・延長へ移動。仮押さえは既存の取消操作を使用。
- 日別参考残数・在庫設定は表の下に配置。商品タブの切り替え時も期間指定を維持する。
- 29件の在庫関連テスト、型チェック、本番ビルド成功。既存DB構造・kintone連携・Sheetsの元入力欄は変更しない。
