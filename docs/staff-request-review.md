# 担当者確認と本登録メール

## 設定

担当者マスターで対象担当者を編集し、「担当者確認を必須にする」をONにする。確認用メールアドレスが必須。初期状態は全員OFF。設定変更は新しい申請に適用し、確認中の申請はOFFにしても継続する。

ON：申請 → 担当者への確認メール → 専用ページで承認 → ユニティ管理者へ通知 → 管理者の最終承認 → kintone本登録。
OFF：従来どおり申請 → ユニティ管理者の承認 → 本登録。

例外：管理者が仮押さえから本登録する際に「社内で本登録するため、電話番号・メールアドレスの入力を省略する」を選択した場合は、担当者確認を省略し、そのまま管理者承認・kintone登録まで進む。公開フォームからこの例外は使用できない。

担当者は専用ページで、申請内容を確認して承認、理由付き差し戻し、または修正を行える。差し戻し時は申請者へ専用の修正リンクを送る。再申請と申請内容の変更は担当者の再確認が必要になる。旧画面の承認・二重承認・期限切れリンクは受け付けない。担当者確認だけではkintoneへ書き込まず、管理者の最終承認も必要。

申請一覧は担当者確認待ち（黄）、申請者修正待ち（赤）、管理者確認待ち（青）を一つの表示にまとめる。詳細の上部に3段階の進捗と次の操作を表示する。

担当事業の管理者は、理由を入力して「管理者が代理承認する」から担当者確認を通過できる。代理承認の操作だけではKintone登録・メール送信せず、続けて通常の最終承認を行う。操作者と理由を履歴に残し、担当者と申請者の旧リンクを無効にする。

「確認URLを再発行」ではメールを送信せず、コピー可能な30日有効のURLを表示する。確認待ちは担当者用、差し戻し中は申請者の修正用を発行する。同じ用途の以前のリンクは無効になる。送信に問題がある場合は詳細画面で確認し、担当者または申請者へ再送できる。

リンクは30日間有効。申請ごとのランダムな専用リンクで、申請者のリンクから担当者承認はできない。共有・転送しない。社内メモや原価などの内部情報は確認ページへ出さない。

## メール本文・ドライブ

システム設定の「メール本文・事業別のドライブリンクを設定する」からメール設定へ進む。

システム設定で事業ごとに資料名と共有URLを複数登録する（最大30件）。メール設定で事業を選択 → 本登録完了メール → ドライブ資料の候補から本文に追加 → 送信イメージを確認して保存。複数の資料を任意の位置に追加できる。既存の共有リンクは「当日運営資料・取扱説明書」として引き継ぐ。資料名・URLを更新しても本文の紐付けは変わらない。本文で使用中の資料は削除できず、先に本文から外す必要がある。

オールマイトとてずくーるは本文もURLも独立。差し込みの内部形式は既存のものを維持し、既存メール・事業別URLは自動変更しない。

## 確認

自動テスト319件。データベース上では架空データを使い、確認OFF、確認ON、両承認段階のゲート、差し戻し、修正・再申請、古い版の拒否、承認後修正での再確認、期限切れ、重複送信防止、社内本登録の確認省略・保存元と管理権限の検証を確認した後、全テストデータを取り消した。

ブラウザーでは担当者・申請者の画面、理由必須、修正開始時の無送信、スマートフォン幅での表示、メールの日本語項目追加・プレビュー・事業別リンク分離を確認。実在する申請者や担当者へのテストメール送信・kintone登録は行っていない。
