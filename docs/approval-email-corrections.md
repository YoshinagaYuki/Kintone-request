# 承認メールの訂正案内

承認前に保存した修正を編集履歴から抽出し、申請時の最初の値→承認時の最終値を案内する。複数回の修正をまとめ、元の値へ戻した項目は訂正対象から外す。企業名・送付先・日付・住所・連絡先・商品・数量などの顧客向け項目だけを許可し、社内メモや内部レンタル費用は対象にしない。

承認画面に各訂正のチェック欄を表示。初期は全項目を選択し、「すべて選択」「記載しない（すべて外す）」も使える。修正があっても0件の選択で承認できる。選択は訂正案内の掲載有無であり、注文内容そのものは確定後の内容を使う。

掲載項目がある場合、件名に【重要：申請内容の訂正】を付け、メール冒頭に赤枠・赤字で「重要：申請内容を訂正しました。必ずご確認ください」、項目名、申請時／訂正後を表示する。0件なら訂正用の件名・赤枠を付けない。どちらも「もし、ご希望と異なる場合は弊社の営業窓口にご相談ください。」を含める。実際の開封や熟読を保証する機能ではない。

メールはHTMLとプレーンテキストの両方を持つmultipart/alternative。テンプレートや入力値のHTMLはすべてエスケープし、HTMLタグ入力を実行可能にしない。承認以外のメールは従来どおり。

サーバーは履歴と確定内容から差分を再生成し、ブラウザのbefore/afterを信用しない。画面の確認署名と差分が一致しない場合は再確認を求める。承認時のparsed_data一致条件でも編集との競合を防ぐ。選んだ差分はrequests.approval_email_correctionsへ承認状態と同時に保存し、登録再試行でも同じ内容を使う。メール送信履歴にも選択内容を残す。既存のapproval_email_sent_atによる二重送信防止を維持する。訂正情報を取得できない場合は訂正なしで送信せずエラーを保存する。

検証：差分の統合・差し戻し・一部選択・0件・不正キー・HTMLエスケープ・multipart生成を自動テスト。架空のローカル画面で複数→0件→集荷日のみを切り替え、メール表示へ一致することを確認。DB保存と0件保存をロールバックするトランザクションで検証。顧客の承認やメール送信は実施しない。
